- **Search engine upgrade** One engine (`services/searchengine.py`) now serves the hub header search, the Cases search box and both portals' Institution Finder. It builds an in-memory index once (names, aliases, place words, initialisms) and rebuilds itself when colleges or aliases change, so a search is dictionary lookups, not a database scan: on a test registry of 15,000 colleges the index builds in about 0.4 s and the slowest search took about 20 ms. It understands initials ("KIP" = Kestora Institute of Pharmacy), partial words, typos, place names and AICTE IDs. Every typed word must match; if none does it falls back to "partial" (some words) and "closest" (spelling) matches, labelled by `tier`, so results are rarely empty (nonsense stays empty). The portals keep the strict "never guess" resolver outcome, and `/api/institutions/search` now also returns `suggestions` that the reporter may pick and confirm (universities are replaced by their colleges).

Roles: RB/PGRC officers get everything; other bureau everything except transfer and escalate; regional office and competent authority can only escalate (with a notice saying so); senior management is read-only. ## Run (Windows, from the project folder)
```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
cd hub\frontend && npm install && cd ..\..
cd hub\backend
python -m app.seed
cd ..\..
python run_all.py
```
To reset the demo any time (also before recording the video): `python reset_demo.py`
